# AI 발제 질문 — P0 프로토타입

`docs/specs/jiwon-discussion-questions.md`의 P0만 구현했다. 모임장 화면 하나, 샘플 기록 파일, 로그인·계정·DB 없음.

## 구성

| 파일 | 하는 일 |
|-|-|
| `server.js` | 작은 Node 서버. 페이지를 보여주고, 생성 요청을 받아 최소 기준 확인 → AI 호출(또는 테스트 응답 읽기) → 검증을 한다. API 키는 이 서버만 읽는다. |
| `lib/core.js` | 핵심 규칙: 최소 기준과 메시지, 임시 라벨, AI에게 보낼 내용, 응답 검증 |
| `prompt.md` | AI에게 주는 지시문. 코드와 분리해 누구나 읽고 고칠 수 있게 했다. |
| `public/` | 모임장 화면 (`index.html`, `app.js`) |
| `data/t1-records.json` | T1용 샘플: 멤버 1명, 밑줄 3개 |
| `data/t2-records.json` | T2·T4용 샘플: 멤버 3명, 밑줄 9개 |
| `data/t4-ai-response.json` | T4용 준비된 AI 응답. 가짜 라벨 `#99`를 근거로 든 질문이 하나 들어 있다. |
| `.env.example` | API 키 자리 예시. 실제 키는 `.env`에 넣는다. |

샘플의 책과 문장은 테스트를 위해 지어낸 것이다.

## 1. 처음 한 번: Node.js 설치

**왜 필요한가:** API 키를 웹 페이지가 아니라 서버 쪽에만 두려면, 내 컴퓨터에서 작은 서버를 돌려야 한다. 이 노트북에는 Python이 없어서, 서버도 화면과 같은 JavaScript로 쓰는 Node.js를 골랐다. T1과 T4는 Node.js만 있으면 추가 설치 없이 돌아간다.

1. https://nodejs.org 에 들어가 **LTS** 버전의 **Windows Installer (.msi)** 를 내려받는다.
2. 설치 파일을 실행하고 기본 설정 그대로 "Next"를 눌러 설치한다.
3. 열려 있던 터미널(PowerShell)을 모두 닫고 새로 연다. 새 터미널이어야 `node` 명령을 찾는다.
4. 확인: 아래를 실행해 `v22` 이상이 나오면 된다.

```
node --version
```

## 2. 실행

레포 폴더에서 터미널을 열고:

```
cd prototypes/jiwon
node server.js
```

브라우저에서 http://localhost:3000 을 연다. 서버를 끄려면 터미널에서 `Ctrl + C`.

## 3. 테스트

### T1 — 최소 기준 차단 (키 없이 됨)

1. `node server.js` 로 서버를 켜고 http://localhost:3000 을 연다.
2. 기록 파일에서 `t1-records.json` 을 고른다. "기록한 멤버 1명 · 밑줄 3개"가 보인다.
3. "발제 질문 만들기"를 누른다.
4. **통과:** 질문이 생성되지 않고 "기록이 더 필요해요. 멤버 1명, 밑줄 2개가 더 있어야 질문을 만들 수 있어요."가 나온다.

### T2 — 근거와 익명 (API 키 필요)

1. 아래 "4. API 키 넣기"를 마친 뒤 `node server.js` 로 서버를 켠다.
2. `t2-records.json` 을 고르고 "발제 질문 만들기"를 누른다.
3. **통과:** 질문 3~4개가 나오고, 화면의 모든 인용문이 `data/t2-records.json` 의 `underline` 문장과 글자 하나까지 같다. 각 인용 아래에 "멤버 n명이 밑줄"만 보이고, 멤버 이름(민지, 도윤, 서연)은 어디에도 보이지 않는다.

키가 없을 때 같은 순서로 하면 "지금 만들 수 없어요"와 "다시 시도" 버튼이 나온다. 이것은 실패가 아니라 키가 없을 때의 정상 동작이다.

### T4 — 없는 라벨 버리기 (키 없이 됨)

1. 서버가 켜져 있으면 `Ctrl + C` 로 끄고, 테스트 모드로 다시 켠다.

```
node server.js --mock data/t4-ai-response.json
```

2. http://localhost:3000 을 열면 화면 위에 "테스트 모드" 안내가 보인다.
3. `t2-records.json` 을 고르고 "발제 질문 만들기"를 누른다.
4. **통과:** 질문이 3개 보이고, "[T4 확인용] … #99 …" 질문은 보이지 않는다. 터미널에는 `[질문 버림] 없는 라벨 #99: …` 이 찍힌다.

## 4. API 키 넣기 (나중에)

**왜 이렇게 하나:** 키가 웹 페이지 코드에 들어가면 페이지를 연 누구나 키를 볼 수 있다. 그래서 키는 서버만 읽는 `.env` 파일에 둔다. `.env` 는 레포의 `.gitignore` 에 들어 있어 커밋되지 않는다.

1. https://console.anthropic.com 에 로그인해 **API Keys** 에서 키를 만든다. 키는 만들 때 한 번만 보이니 바로 복사한다. 결제 수단이나 크레딧이 있어야 호출된다.
2. `prototypes/jiwon/.env.example` 을 복사해 같은 폴더에 `.env` 를 만든다.

```
copy .env.example .env
```

3. `.env` 를 열어 `ANTHROPIC_API_KEY=` 뒤에 키를 붙여 넣고 저장한다. `.env.example` 에는 키를 넣지 않는다.
4. Anthropic SDK를 설치한다 (처음 한 번). PowerShell에서 "스크립트를 실행할 수 없습니다" 오류가 나면 `npm` 대신 `npm.cmd` 를 쓴다.

```
npm install
```

5. 서버를 다시 켠다: `node server.js`
6. 커밋 전에 `git status` 로 `.env` 가 목록에 나오지 않는지 확인한다.

## 동작 메모

- 모델: Claude Haiku 5.5 (`claude-haiku-5-5`). 응답은 정해진 JSON 형식으로 받는다.
- AI에게는 멤버 이름이나 ID를 보내지 않는다. 같은 문장은 하나로 묶어 `#1`, `#2` 라벨과 "멤버 n명이 밑줄" 숫자만 보낸다.
- AI는 근거로 라벨만 고른다. 화면의 인용문은 원본 기록 파일에서 가져온다.
- 질문을 버리는 경우: 근거 라벨 중 하나라도 없는 라벨일 때, 근거가 없을 때, 근거가 2개보다 많을 때. 버린 질문은 터미널에 찍힌다.
- 남은 질문이 1개 이상이면 그대로 보여주고, 0개이거나 API가 실패하면 "지금 만들 수 없어요"와 "다시 시도"를 보여준다. 실패해도 같은 화면의 직전 결과는 지우지 않는다.
- 키가 없거나 SDK가 설치되지 않았을 때도 서버는 멈추지 않고 "지금 만들 수 없어요"를 보여준다. 이유는 터미널에 찍힌다.

# 모임 기록·요약 — P0 프로토타입

`docs/specs/Minyeong-meeting-summary.md`의 P0만 구현했다. 화자가 구분된 대화 텍스트를 넣고 화자에게 실명을 맞추면, Claude가 한 줄 요약, 쟁점 카드(최대 3개), 멤버 카드, 남은 질문, 그 밖에 나온 이야기로 정리한다. 그 밖에 나온 이야기는 [더 알아보기]로 쟁점 카드처럼 펼칠 수 있다. 쟁점 카드마다 AI가 제안하는 "더 생각해 볼 질문"이 대화 기록과 구분되어 붙는다. 녹음, 로그인, 저장, 자유 질문은 없다(P1).

읽을 수 있는 대화 형식은 두 가지다.

```
참석자 1: 저는 이기적이었다고 봐요.        ← '화자: 발언' 한 줄 형식

참석자 1 00:03                           ← 클로바노트 내보내기 형식
저는 이기적이었다고 봐요.
```

## 구성

| 파일 | 하는 일 |
|-|-|
| `server.py` | 작은 Python 서버. 화면을 보여주고, 정리 요청을 받아 AI 호출(또는 테스트 응답 읽기) → 결과 정리를 한다. API 키는 이 서버만 읽는다. |
| `summarize.py` | 핵심 규칙: 대화 읽기(`이름: 발언`), AI 호출과 실패 처리, 쟁점·남은 질문 개수 제한, 인용 확인 |
| `prompt.md` | 정리하기에서 AI에게 주는 지시문. 코드와 분리해 누구나 읽고 고칠 수 있게 했다. |
| `prompt-expand.md` | [더 알아보기]에서 AI에게 주는 지시문 |
| `public/index.html` | 화면 |
| `data/sample-meeting.txt` | C1용 샘플 대화: 멤버 4명, 의견이 갈리는 질문 3개 |
| `data/c2-ai-response.json` | C2용 준비된 AI 응답. 지어낸 인용 1개, 다른 사람의 말을 옮긴 인용 1개가 들어 있다. |
| `.env.example` | API 키 자리 예시. 실제 키는 `.env`에 넣는다. |

샘플의 책(『여름의 끝에서』)과 대화는 테스트를 위해 지어낸 것이다.

## 1. 처음 한 번: 준비

**왜 Python인가:** API 키를 웹 페이지가 아니라 서버 쪽에만 두려면 내 컴퓨터에서 작은 서버를 돌려야 한다. 이 노트북에는 Node.js가 없고 Python이 있어서 Python 표준 라이브러리로 서버를 만들었다. 추가로 필요한 것은 Claude 공식 SDK 하나다.

```
cd prototypes/Minyeong
python -m pip install -r requirements.txt
```

## 2. API 키 넣기

**왜 이렇게 하나:** 키가 웹 페이지 코드에 들어가면 페이지를 연 누구나 키를 볼 수 있다. 그래서 키는 서버만 읽는 `.env` 파일에 둔다. `.env`는 레포의 `.gitignore`에 들어 있어 커밋되지 않는다.

1. `.env.example`을 복사해 같은 폴더에 `.env`를 만든다.
2. `ANTHROPIC_API_KEY=` 뒤에 console.anthropic.com에서 만든 키를 붙여 넣고 저장한다.
3. 키를 채팅이나 다른 파일에 붙여 넣지 않는다.

## 3. 실행

```
cd prototypes/Minyeong
python -X utf8 server.py
```

브라우저에서 http://localhost:8000 을 연다. 끄려면 터미널에서 `Ctrl + C`. `.env`를 고친 뒤에는 서버를 껐다 다시 켠다.

## 4. 손으로 해 볼 점검

### C1 — 4가지 정리 (API 키 필요)

1. 서버를 켜고 "샘플 대화 불러오기" → "정리하기". 1분 정도 걸릴 수 있다.
2. **통과:** 한 줄 요약, 쟁점, 멤버, 남은 질문이 모두 나온다. "선우가 떠난 것은 이기적이었나" 쟁점에서 하늘(책임이 먼저)과 도윤(살기 위한 선택)의 다른 생각이 이름과 함께 구분되어 보이고, 갈린 이유와 공통점(평생 후회했다)이 나온다.

### C2 — 근거 인용

1. C1 결과 화면의 인용문을 `data/sample-meeting.txt`에서 검색해(Ctrl + F) 실제로 그 사람의 발언에 있는지 확인한다. 없는 인용에는 "근거 확인 안 됨"이 붙어 있어야 한다.
2. 서버를 끄고 테스트 모드로 다시 켠다.

```
python -X utf8 server.py --mock data/c2-ai-response.json
```

3. 화면 위에 "테스트 모드" 안내가 보인다. "샘플 대화 불러오기" → "정리하기".
4. **통과:** 하늘의 인용에는 표시가 없고, 도윤(지어낸 인용)과 서연(도윤의 말을 서연의 것으로 옮김)의 인용에는 "근거 확인 안 됨"이 붙는다. 두 항목은 숨겨지지 않고 보인다. 터미널에 `[근거 확인 안 됨]` 두 줄이 찍힌다. 멤버 카드에 서연이 없고 "그 밖에 나온 이야기"도 없는 것은 테스트 응답이 그렇게 만들어졌기 때문이다.

### C4 — 화자 이름 맞추기 + 더 알아보기 (API 키 필요)

1. 서버를 일반 모드(`python -X utf8 server.py`)로 켠다.
2. `참석자 1, 2`로 표시된 실제 녹음 대화를 대화 칸에 붙여 넣는다. 아래에 "화자 이름 맞추기"가 나타나고, 화자마다 첫 발언 한 줄이 보인다.
3. 화자마다 실명을 적고 "정리하기".
4. "그 밖에 나온 이야기" 중 하나에서 [더 알아보기]를 누른다.
5. **통과:** 정리 결과 어디에도 `참석자 n`이 아니라 적은 실명이 보이고, 펼친 카드에 실명별 생각과 인용, 갈린 이유, 공통점이 나온다. 이름을 비워 둔 화자는 `참석자 n`으로 그대로 보인다.

테스트 모드(`--mock`)에서는 [더 알아보기]를 누르면 "지금 펼칠 수 없어요"가 나온다. 준비된 응답이 정리하기용 하나뿐이기 때문이다.

### C5 — AI 제안 질문 (C1 결과로)

1. C1 결과의 쟁점 카드마다 맨 아래 보라색 점선 칸 "AI 제안 · 더 생각해 볼 질문"을 읽는다.
2. **통과:** 카드마다 질문이 1~2개이고, 대화 기록과 색·제목이 달라 구분된다. 질문이 그 카드의 갈린 이유나 멤버의 생각을 이어받는다(어느 책에나 쓸 수 있는 일반 질문이 아니다).

### C3 — 호출 실패

1. 서버를 끄고 `.env`의 키 끝에 글자 몇 개를 덧붙여 틀린 키로 만든 뒤 서버를 켠다.
2. "샘플 대화 불러오기" → "정리하기".
3. **통과:** "지금 정리할 수 없어요"와 "다시 시도" 버튼이 나오고, 위의 대화 칸 내용이 그대로 남아 있다. 터미널에 `[정리 실패] API 키가 올바르지 않아요 (401)`이 찍힌다.
4. 점검이 끝나면 `.env`의 키를 원래대로 되돌린다.

## 참고

- 모델: Claude Sonnet 5.5 (`claude-sonnet-5-5`). 안전 분류기가 요청을 거절하면 서버 쪽 대체 모델 기능(`fallbacks: "default"`)이 같은 요청을 다른 모델로 다시 처리한다.
- 인용 비교는 공백 차이만 무시한다. 문장부호 차이까지 허용할지는 C2 결과를 보고 정한다(스펙 "열린 문제").

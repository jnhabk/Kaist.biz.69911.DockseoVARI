# 독서 감상 기록 — P0 프로토타입

`../../docs/specs/jisu-readingjournal.md`의 P0 첫 시험 범위를 구현합니다. UI·API·JSON 파일 저장을 `prototypes/jisu/` 아래에 독립 구성했으며 외부 Node 패키지는 필요하지 않습니다.

## 포함한 흐름

- 닉네임 게스트로 공간을 만들고 초대 링크로 참여합니다. 개인 접속 링크와 초대 링크는 서로 다른 비밀값입니다. 개인 링크는 브라우저에 저장되고 서버에는 해시만 저장합니다. 분실하면 공간 모임장이 재발급할 수 있습니다.
- 같은 게스트로 여러 공간에 참여하고 전환할 수 있습니다. API에서 공간 멤버십을 검사해 다른 공간의 회차와 기록을 섞지 않습니다.
- 회차 생성·일정 변경, host 지정, 참석 응답, 취소, 카카오 Daum 책 검색과 직접 등록을 지원합니다. 책 변경은 기록이 남아 있으면 막습니다.
- 문구나 생각을 여러 건 기록하고 공개 범위를 바꾸거나 수정·삭제할 수 있습니다. 나만 보기 원문은 작성자에게만 API 응답합니다.
- 참석자만 참여율에 포함하고 시작 시점에 준비 상태를 고정합니다. 서버는 15초 간격으로 시작과 마감 작업을 확인합니다.
- 준비 마감에 첫 발제문을 자동 생성하고, 실패하면 1분 간격으로 최대 세 번 시도합니다. host는 모임 당일에 AI 발제문을 재생성할 수 있습니다. 최초 생성이 끝내 실패했을 때는 host가 수기 발제문을 저장할 수 있습니다.
- host 제공 본문과 선택 링크를 저장합니다. AI는 본문만 참고하고 링크를 따라가지는 않습니다. 웹 푸시, 로그인 계정, 바코드·사진 등록, 아카이브 탐색은 만들지 않았습니다.

## 로컬 실행

필요한 런타임은 Node.js 22 이상입니다. 패키지 설치나 데이터베이스 설치는 필요하지 않습니다.

1. PowerShell에서 저장소의 프로토타입 폴더로 이동합니다.

   ```powershell
   Set-Location 'C:\Users\pgs56\devel\Kaist.biz.69911.DockseoVARI\prototypes\jisu'
   ```

2. 설정 예시를 복사하고 로컬 설정 파일을 엽니다. `.env`는 Git에 커밋되지 않습니다.

   ```powershell
   Copy-Item .env.example .env
   notepad .env
   ```

3. `node --version`에서 v22 이상이 확인되면 다음을 실행합니다.

   ```powershell
   node server.mjs
   ```

   현재 개발 노트북에서 `node` 명령을 찾지 못하면 설치된 Node를 쓰거나 Codex 번들 Node로 실행할 수 있습니다.

   ```powershell
   & 'C:\Users\pgs56\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe' server.mjs
   ```

4. 브라우저에서 [http://localhost:3030](http://localhost:3030)을 엽니다. 서버를 끄려면 터미널에서 `Ctrl+C`를 누릅니다.

`data/store.json`에 닉네임, 공간, 회차, 기록이 저장됩니다. 로컬 프로토타입 기록은 평문이므로 실제 민감한 독서 기록을 넣기 전에 아래의 공유 범위를 확인하세요. 이 파일은 `.gitignore`에 포함되어 있습니다.

## 도서 검색과 AI 발제문 설정

둘 다 선택 설정입니다. 키는 브라우저에 전달하지 않고 Node 서버만 읽습니다.

### 국내 책 검색

검색 API 키가 없으면 도서 검색은 동작하지 않지만 제목·저자를 직접 입력해 회차를 만들 수 있습니다.

1. [Kakao Developers](https://developers.kakao.com/)에서 앱을 만들고 앱 키 중 **REST API 키**를 확인합니다.
2. `.env`의 `KAKAO_REST_API_KEY=` 뒤에 키를 넣고 저장합니다. JavaScript 키나 Admin 키가 아니라 REST API 키를 사용합니다.
3. 서버를 재시작합니다.

Kakao REST API 키는 서버에만 보관합니다. [Kakao Daum 책 검색 문서](https://developers.kakao.com/docs/ko/daum-search/dev-guide#search-book)에 명시된 REST API를 호출합니다. 네이버 개발자센터 Search API가 2026-07-31 종료 공지를 했기 때문에 사용 가능한 국내 도서 검색 제공자로 연결했습니다. 출시 전에 Kakao 책 검색 이용 조건과 검색 품질을 다시 확인하세요. [네이버 Search API 종료 공지](https://developers.naver.com/notice/article/32564)

### AI 발제문 생성

1. [Anthropic Console](https://console.anthropic.com/)에서 API 키를 발급하고 사용할 계정의 결제·사용 한도를 확인합니다.
2. `.env`의 `ANTHROPIC_API_KEY=` 뒤에 키를 붙여 넣고 저장합니다. `ANTHROPIC_MODEL`은 필요할 때 계정에서 사용할 수 있는 모델 ID로 바꿉니다.
3. 서버를 재시작합니다.

키가 비어 있거나 API 호출에 실패하면 화면에 실패 상태가 표시되고 자동 재시도합니다. 최초 생성이 실패한 회차에는 host 수기 작성이 열립니다. AI 생성에는 Anthropic 사용량 비용이 발생할 수 있습니다. 이 프로토타입의 모델·API 제공자는 시험용 결정이며, 명세에서 비용·이용 조건을 확인해 확정해야 합니다.

## 네 명의 첫 시험에 필요한 네트워크

`localhost`는 이 컴퓨터의 브라우저만 접근할 수 있습니다. 네 명이 각자 기기에서 접속하려면 Node 서버가 한 주소에서 계속 실행되고, 참여자 기기에서 그 주소에 도달할 수 있어야 합니다. 저장은 단일 JSON 파일이므로 동시에 여러 서버를 띄우거나 임시 디스크가 있는 서버에 배포하면 데이터가 유실되거나 충돌할 수 있습니다.

같은 신뢰할 수 있는 Wi-Fi에서 짧게 시험할 때:

1. `.env`에서 `HOST=0.0.0.0`으로 바꾸고 서버를 실행합니다.
2. Windows 방화벽의 **개인 네트워크**에서 TCP 3030 인바운드를 허용합니다. 관리자 PowerShell에서 다음 명령을 사용하고 시험 후 규칙을 제거하세요.

   ```powershell
   New-NetFirewallRule -DisplayName 'Readingjournal P0' -Direction Inbound -Protocol TCP -LocalPort 3030 -Action Allow -Profile Private
   ```

   제거할 때는 `Remove-NetFirewallRule -DisplayName 'Readingjournal P0'`를 실행합니다.

3. `ipconfig`에서 노트북의 Wi-Fi IPv4 주소(예: `192.168.0.20`)를 확인합니다. 참여자들은 `http://192.168.0.20:3030`처럼 그 주소를 엽니다. 초대 링크는 브라우저 주소를 기준으로 발급되므로 같은 노트북의 초대 창에서 만들어 전달합니다.
4. 네 명이 각각 다른 브라우저 프로필이나 기기를 써서 초대·기록·비공개 원문 접근 범위를 확인합니다. 노트북과 서버는 시험 중 켜 둡니다.

이 방식은 **동일한 신뢰 네트워크에서만** 사용하세요. HTTP라 링크의 개인 접속 토큰이 암호화되지 않습니다. 다른 네트워크에서 접속해야 하는 시험에는 HTTPS, 인터넷에서 제한된 접근, 영구 저장 디스크와 백업이 있는 Node 호스팅을 마련하고, 이 JSON 저장을 동시 요청에 안전한 데이터베이스로 교체해야 합니다. 현재 코드는 공개 인터넷 배포용 인증·암호화·운영 구성이 아닙니다.

## 동작 확인 순서

1. 설정 없이 실행해 공간을 만들고 개인 접속 링크와 초대 링크가 별도로 나오는지 확인합니다.
2. 별도 브라우저 프로필에서 초대 링크로 참여하고 닉네임을 입력합니다. 모임장 화면의 멤버 목록에 참여자가 나타나는지 확인합니다.
3. 새 회차를 만들어 수동으로 책을 등록합니다. 시작·종료, 12시간 또는 24시간 마감, host를 지정합니다. 키를 설정한 경우 도서 검색도 확인합니다.
4. 네 명이 참석으로 응답하고 세 명 이상이 공개 또는 비공개 기록을 남기면 준비 완료가 3/4 이상으로 표시되는지 확인합니다. 불참·미응답 멤버의 기록은 참여율에서 제외됩니다.
5. 비공개 기록은 작성자 브라우저에서만 보이는지 확인합니다. 다른 멤버의 화면에서 원문이 응답·화면에 나타나면 안 됩니다.
6. AI 키가 있을 때 마감이 지난 회차를 만들어 자동 발제문을 확인합니다. 수동 확인은 모임 당일에 host가 AI 생성을 누릅니다. 키 없이 실패 흐름을 확인하면 재시도 후 최초 생성 실패 시 host 수기 입력이 열립니다.
7. 회차 시작 시점의 스냅샷을 확인하려면 서버를 계속 켜 둡니다. 시작 이후 참석·기록을 바꿔도 고정된 준비율이 유지되는지 확인합니다.

## 구현상 제한

- 이 프로토타입은 한 대의 Node 프로세스와 로컬 JSON 파일로 동작합니다. 사용자 계정·이메일 인증, DB 백업·복구, 운영 배포 수준의 보안은 포함하지 않습니다.
- 서버가 꺼져 있는 동안 회차 시작 시각이 지나면 정확한 시작 시점 스냅샷을 복원할 수 없습니다. 시작 전부터 서버를 계속 실행하세요.
- Kakao Daum 검색 결과가 모든 한국 도서를 포함한다고 보장하지 않습니다. 결과가 없으면 직접 등록하세요.
- AI 출력은 스키마·개인정보 규칙을 검사하지만, 언어모델 출력의 의미 수준 개인정보 노출을 완벽히 증명할 수는 없습니다. 첫 시험에서 host가 발제문을 확인하세요.
- 실제 푸시 알림, 계정 가입, 이미지 OCR, 바코드, 후기 평가는 P2라 제외했습니다.

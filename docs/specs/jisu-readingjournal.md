# jisu-readingjournal — 개인 독서 감상 기록 기능 명세

작성자: Jisu / 작성일: 2026-10-29 / 상태: 인터뷰 합의 기반, 구현 전

## 1. 대상과 문제 발생 시점

대상은 독서 모임 참여자와 회차별 진행자(host)다. 참여자는 책을 읽다가 인상적인 문구·생각을 발견했지만 기록을 미루거나, 모임 전에 이야기할 내용을 정리하지 못한다. host는 참여자의 관심사를 모르는 상태에서 발제문을 준비해야 한다.

개인의 입력 부담을 낮춰 모임 전에 기록을 수집하고, AI가 그 기록을 실제 대화 질문으로 연결한다. 독립적인 개인 서재보다 모임 준비와 운영이 우선이다.

## 2. WhyTree 연결

원본은 사용자가 첨부한 whytree.md다. 원본 트리를 수정하는 대신 이번 구현의 우선 목적을 구분한다.

- 대상 노드: **개인 독서 감상 기록 [씨앗]**.
- 원본 주된 연결: 개인 독서 감상 기록 → 독서 활동과 생각의 축적 → 읽고 생각하는 자신에게 성취감 느끼기.
- 원본 부가 연결: 개인 독서 감상 기록 → 나누고 싶은 생각의 표현 → 흥미와 공감을 나누는 대화 → 새로운 관점과 배움 얻기 / 관심사를 나누는 연결감 느끼기.
- 이번 구현은 부가 연결인 **생각의 표현과 모임의 대화**를 우선 검증한다.
- 기록을 AI 발제문 추천 [씨앗]의 입력으로 사용한다. AI 도서 추천 [씨앗] 활용은 후속이다.
- 최상위 목적: 함께 읽고 생각을 나누며 삶을 풍요롭게 하기.

## 3. 우선순위

- **P0 — must ship:** 첫 4명 시험에 반드시 제공.
- **P1 — if time allows:** P0 완료 후 여유가 있을 때 제공.
- **P2 — later:** 후속 단계, 첫 시험 범위 밖.

## 4. 사용자 흐름 — P0

### 4.1 공간 생성·참여

1. 생성자가 닉네임으로 게스트 접속해 공간을 만들고 공간 모임장이 된다.
2. 개인 접속 링크·코드를 발급하고 본인만 보관하도록 안내한다. 같은 브라우저에서는 접속 상태를 유지한다.
3. 모임장은 초대 링크·QR·코드를 전달한다. 초대 수단은 개인 접속 수단과 구분한다.
4. 유효한 초대를 받은 사람은 닉네임을 입력하고 승인 없이 참여한다.
5. 모임장은 초대를 만료하거나 새로 발급할 수 있다.
6. 멤버는 자기 공간의 데이터만 본다. A·a의 기록은 B·b 공간에서 보이지 않는다.
7. 나중에 합류한 멤버도 과거 모임·공개 기록·발제문을 볼 수 있다. 비공개 원문은 제외한다.
8. 한 사람이 여러 공간에 참여하고 선택·전환할 수 있다. 게스트의 공간 간 신원 연결 방식은 구현 시 확정한다.

### 4.2 회차 생성

1. 누구나 회차를 생성한다.
2. 국내 도서를 제목·저자로 검색하고, 없으면 직접 등록한다.
3. 제목·저자·표지를 화면에 필수 표시한다. 표지가 없으면 제목·저자 기반 대체 표지를 쓰고 나중에 실제 표지를 추가한다.
4. 회차 하나에 책 한 권만 지정한다.
5. 시작 시각 입력 시 종료는 2시간 뒤로 채우고 수정 가능하게 한다.
6. 준비 마감은 시작 24시간 전 또는 12시간 전 중 선택한다. 별도 마감 날짜 입력은 요구하지 않는다.
7. 생성자가 회차 host를 지정한다. 이후 일정·책 수정은 host가 한다. 공간 모임장은 host 변경 가능하다.
8. 멤버별 참석·불참·미응답을 선택한다. 기본은 미응답이다.

### 4.3 개인 기록 작성

1. 회차 화면에서 책·일정·마감·참석 상태·준비 현황을 확인한다.
2. 책 속 문구 또는 내 생각을 입력한다. 둘 중 하나는 필수이고 페이지 번호는 선택이다.
3. 내 생각은 입력란 하나다. ‘왜 인상 깊었나요?’, ‘관련된 경험이 있나요?’, ‘함께 이야기하고 싶은 것은?’을 힌트로 표시한다. 질문 선택 단계는 없다.
4. 공개 범위를 고른다. 기본은 모두 공개이고 나만 보기로 바꿀 수 있다.
5. 저장 전에 원문 공개 대상과 비공개 기록의 AI 활용을 안내한다.
6. 저장하면 해당 회차에 연결한다. 한 사람이 여러 건 작성 가능하다.
7. 공개 기록은 즉시 작성자 이름과 함께 공간 전체에 보인다. 본인 기록을 먼저 작성할 필요는 없다.
8. 비공개 기록은 작성자만 원문을 본다. 참석자의 비공개 기록은 AI 입력으로 활용한다.

### 4.4 발제문과 모임

1. 준비 마감에 시스템이 최초 발제문을 자동 생성한다.
2. 생성 당시 참석 상태인 멤버의 기록만 사용한다. 불참·미응답자의 기록은 보관하되 AI 입력에서 제외한다.
3. 기록이 없으면 허용된 책 자료로 생성한다. 자료도 부족하면 범용 질문을 제공한다.
4. 생성 즉시 전원에게 공개한다. 별도 공개 승인은 없다.
5. 한국 시간 기준 모임 당일이면서 예정 종료 전까지 해당 host가 수동 생성·재생성할 수 있다.
6. 모임 시작 이후 자동 갱신은 중단하고, 종료 이후 수동 재생성도 중단한다.
7. 종료된 회차는 최종 발제문과 기록을 열람한다.

## 5. 준비 상태와 검증 — P0

- 현재 기록 한 건 이상이면 준비 완료다. 나만 보기 기록도 인정한다.
- 마지막 기록을 삭제하면 미작성으로 돌아간다.
- 모든 멤버가 참석자의 이름별 준비 완료·미작성 상태를 볼 수 있다. 비공개 원문이나 공개 범위는 준비 현황에 표시하지 않는다.
- 참석자만 참여율 분모와 준비 요청 대상에 포함한다.
- 준비 마감 이후·시작 이전 기록도 준비 완료와 성공 지표에 포함한다. 이미 생성한 발제문에는 다음 재생성 때 반영한다.
- **준비 마감은 최초 AI 생성 기준, 모임 시작은 참여율 집계 기준**이다.
- 시작 시점의 참석자와 기록 보유 상태를 고정한다. 이후 참석 변경·기록 수정으로 과거 지표를 바꾸지 않는다.
- 성공 기준: 참석자 **4명 중 3명 이상**, 즉 75% 이상이 시작 시점에 기록 보유.
- 실제 대화에 쓰였는지는 모임 후 인터뷰로 확인한다. 기록을 반영한 질문이 논의됐는지 묻는다. 앱 내 평가 기능은 만들지 않는다.
- 첫 시험은 웹 푸시 없이 진행하므로 알림 효과를 검증한 결과로 해석하지 않는다.

## 6. 공개·AI 활용 — P0

| 종류 | 원문 열람 | AI 활용·출력 |
|---|---|---|
| 모두 공개 | 공간 멤버 전체, 작성자 이름 표시 | 참석자 기록만 활용, 작성자를 지목하지 않음 |
| 나만 보기 | 작성자만 | 참석자 기록은 활용, 개인 생각·경험을 직접 인용하거나 구체적 정황을 노출하지 않고 일반적인 질문으로 변환 |
| 책 속 문구 | 기록 공개 범위에 따름 | 직접 인용 가능. 향후 사진에서 추출한 책 문구도 동일 |

- ‘누구님이 이렇게 생각했다’, ‘누구님이 인상 깊게 읽었다’는 표현은 금지한다.
- 공개 원문에는 이름이 있으므로 완전한 익명성을 보장하는 서비스는 아니다.
- 공개 범위는 종료 후에도 양방향 변경 가능하다. 나만 보기로 바꾸면 즉시 원문을 숨긴다.
- 기록 수정·삭제·공개 범위 변경 및 참석 상태 변경은 기존 발제문을 자동 변경하지 않는다. 다음 재생성 때 반영한다. 탈퇴의 시작 전 자동 갱신은 별도 예외다.

## 7. 발제문 내용과 자료 — P0

### 기본 구성

- 시작 질문 1개: 전체적인 인상.
- 핵심 질문 3개: 참석자 기록에 담긴 주제.
- 마무리 질문 1개: 대화 후 달라진 생각.
- 질문마다 보조 질문 1개.
- 부족한 기록은 책 자료·범용 질문으로 보완한다. 책의 장면·결말을 추측하지 않는다.

### 출처

- 국내 도서 API의 이용 가능한 검색·ISBN·표지·소개 자료와 출판사 공식 소개로 제한한다.
- 구체적인 API 제공사는 구현 단계에서 이용 조건·제공 범위를 확인해 선정한다.
- 개인 블로그·커뮤니티·출처 불명 요약·AI 기억에 의존한 줄거리는 사용하지 않는다.
- 사용한 외부 자료는 제공처와 링크를 표시한다.
- host는 본문과 선택적인 출처 링크를 보충할 수 있다. AI는 붙여 넣은 본문만 사용하며 링크를 자동 수집하지 않는다.
- 보충 자료는 ‘host 제공 자료’로 공식 자료와 구분한다. 회차의 참고 자료에서 모두 열람 가능하다.
- 기록이 없으면 그 사실을 안내한다. 책 자료도 없으면 자료 부족을 안내하고 범용 질문을 만든다. 자료 부족은 기술적 실패가 아니다.

### 실패와 수기 작성

- AI 장애·제한·응답 검증 실패·저장 실패 등은 자동 재시도하고 생성 상태·실패를 웹에 표시한다.
- 발제문이 한 번도 생성되지 못한 경우에만 host에게 당일 전에도 다시 시도와 수기 작성을 허용한다.
- 일반적인 발제문 직접 편집은 제외한다. 최초 실패 시 수기 작성만 예외다.
- 수기 발제문 저장은 즉시 공개하며 자동 재시도를 중단한다. 진행 중 AI 결과도 덮어쓰지 못한다.
- 당일 host가 AI 재생성을 선택하면 수기 내용을 교체한다는 확인을 받는다.
- 재생성 실패 시 기존 AI·수기 발제문을 유지한다.

## 8. 기록의 수정·삭제 — P0

- 종료 전에는 작성자가 기록을 수정·삭제할 수 있다.
- 종료 전에 작성한 기록은 종료 후 삭제 불가, 수정만 가능하다.
- 종료 후 새 기록 추가는 가능하고, 그 기록은 수정·삭제 모두 가능하다.
- 종료 후 추가·수정 내용으로 최종 발제문을 갱신하지 않는다.
- 최신 내용만 표시한다. 수정됨·최종 수정 시각을 제공하고 수정 이력은 제공하지 않는다.
- 탈퇴 시 비공개 삭제는 종료 후 삭제 제한보다 우선한다.

## 9. 일정·책·취소 — P0

### 일정 변경

1. 기존 24시간 전 / 12시간 전 선택을 유지해 마감을 다시 계산한다.
2. 미발송 알림만 새 일정에 맞추고 이미 보낸 알림은 반복하지 않는다. 실제 푸시는 P2다.
3. 새 마감이 지났으면 지난 알림은 생략하고 발제문이 없을 때만 즉시 생성한다.
4. 기존 발제문은 유지하고 새 모임 당일 host가 재생성할 수 있다.
5. 웹에 일정 변경을 표시한다. P2에서는 허용 시간대의 푸시도 제공한다.

### 책 변경

- 현재 개인 기록이 0건이면 변경 가능하다. 과거 작성 이력이 있어도 모두 삭제했으면 가능하다.
- 기록이 있으면 다른 책으로 바꾸기 위해 새 회차를 만든다. 제목·저자·표지 오류 수정은 허용한다.
- 책 변경 시 기존 발제문·보충 자료 삭제를 확인받는다.
- 이전 발제문·자료를 삭제하고 새 책으로 준비 마감 전이면 예약, 이후이면 즉시 생성한다.

### 취소

- 해당 host 또는 공간 모임장이 취소 가능하다.
- 취소 확정 후 복구 불가, 다시 진행하려면 새 회차를 만든다.
- 예약 알림·발제문 생성·재생성을 중단한다.
- 새 기록은 막고 기존 기록·발제문은 취소된 회차에 보존한다. 기존 기록은 작성자가 삭제할 수 있다.
- 취소와 종료 후 삭제 제한이 겹치는 상황은 출시 전 세부 규칙을 확정한다.

## 10. 권한·탈퇴·복구 — P0

| 주체 | 권한 |
|---|---|
| 멤버 | 회차 생성과 최초 host 지정, 본인 참석·기록 관리, 공개 자료 열람 |
| 회차 host | 일정·책·보충 자료 관리, 허용 시간 수동 생성·재생성, 실패 시 수기 작성, 취소 |
| 공간 모임장 | 초대·멤버 관리, host 변경, 취소, 개인 접속 수단 재발급 |
| 시스템 | 마감 최초 생성, 실패 재시도, 시작 전 탈퇴 반영, 지표 고정 |

- 개인 접속 링크·코드는 본인의 비공개 원문까지 여는 비밀 열쇠다. 초대용 수단과 분리한다.
- 모임장은 본인임을 별도로 확인한 후 멤버 링크를 재발급한다. 기존 링크·코드와 세션을 무효화하고 기록·권한은 유지한다.
- 모임장이 접속 수단을 모두 잃으면 운영자가 확인 후 수동 복구한다. 전용 화면은 제외한다.
- 회차 host 탈퇴·내보내기 시 공간 모임장에게 자동 이관하고 웹에 알린다. 모임장이 다시 지정 가능하다.
- 공간 모임장은 다른 멤버에게 권한을 넘긴 후 탈퇴한다. 본인 회차 host도 새 모임장에게 넘긴다.
- 마지막 한 명이어도 공간을 유지한다. 원할 때 별도로 공간을 삭제할 수 있다.

### 탈퇴자 기록

1. 종료 여부와 관계없이 나만 보기 원문 삭제.
2. 공개 원문은 탈퇴한 멤버로 유지.
3. 이후 AI 입력에서 탈퇴자 기록 제외. 유지된 공개 기록도 동일.
4. 발제문 생성 후·시작 전 탈퇴라면 해당 기록을 제외해 자동 갱신. 일반 당일 재생성 제한의 예외.
5. 시작 이후 자동 갱신하지 않으며 종료 후 발제문 보존.

## 11. 후속 알림 — P2

- 한국 시간 기준 준비 마감 24시간 전·12시간 전에 미작성 참석자에게 푸시한다.
- 허용 시간은 07:00 이상 24:00 미만. 00:00~06:59 예정 알림은 당일 07:00으로 미룬다.
- 조정 시각이 마감 이후면 생략한다. 두 알림이 겹치면 한 번만 보낸다.
- 발송 직전에 참석·기록 상태를 확인한다. 기록을 모두 삭제해 미작성으로 돌아온 사람도 조건에 맞으면 대상이다.
- 늦은 초대·등록으로 지난 알림은 소급 발송하지 않는다. 마감 후 준비 요청 중단.
- 일정 변경 시 미발송 예약만 조정하고 취소 시 모두 중단한다.
- 일정 변경 푸시도 허용 시간대에 발송한다.
- 푸시 미지원·미허용 사용자도 참여하며 웹 내 마감·상태를 제공한다.
- Android 지원 브라우저 알림 허용, iPhone 지원 버전의 홈 화면 웹앱 추가·알림 허용 등 기기 조건을 안내한다.

## 12. 후속 계정과 확장 — P2

- 카카오·구글·이메일 가입을 모두 제공한다. 이메일 인증 후 비밀번호 로그인·재설정을 지원한다.
- 게스트 기록·멤버십·권한을 계정에 연결한다. 연결 완료 후 기존 게스트 개인 접속 수단은 무효화한다.
- 같은 이메일이어도 자동 병합하지 않는다. 기존 방식 로그인으로 본인 확인 후 로그인 수단을 연결한다.
- 바코드 ISBN 검색과 직접 등록을 함께 제공한다.
- 사진 문자 인식 후 확인·수정한 문구를 저장하고 생각은 선택 입력한다.
- 동일 기록을 책별·일정별로 조회할 수 있도록 확장한다.
- 댓글·공감과 기록 기반 다음 책 추천은 후속이다. 상세 정책은 추가 설계한다.

## 13. 화면·데이터 설계 초안 — P0

합의된 행동을 구현하기 위한 초안이며 특정 기술 스택은 미확정이다.

### 화면

1. 공간 생성·초대 참여·개인 접속 링크 보관 안내.
2. 공간 선택·홈: 회차 목록, 멤버·초대 관리 진입.
3. 회차 생성·수정: 도서, 시작·종료, 마감 선택, host.
4. 회차 상세: 참석 응답, 준비 현황, 공개·본인 기록, 발제문·생성 상태, 참고 자료.
5. 기록 작성·수정: 문구, 내 생각, 페이지, 공개 범위, AI 활용 안내.
6. host 작업: 자료 보충, 재생성, 최초 실패 수기 작성, 취소.
7. 모임장 작업: 초대·멤버·host 관리, 개인 접속 수단 재발급.

### 데이터

| 개체 | 주요 정보 |
|---|---|
| 게스트 신원·접속 | 닉네임, 접속 토큰 검증값, 세션, 폐기 여부 |
| 공간·멤버십 | 공간, 사용자, 모임장 여부, 참여·탈퇴 상태 |
| 초대 | 공간, 코드·토큰, 유효 상태 |
| 책 | 제목, 저자, 표지·대체 표지, ISBN·제공처 식별자 |
| 회차 | 공간, 책, host, 시작·종료, 마감 오프셋, 취소 상태 |
| 참석 응답 | 회차, 멤버, 참석·불참·미응답 |
| 개인 기록 | 회차, 작성자, 문구, 생각, 페이지, 공개 범위, 작성·수정 시각 |
| 참고 자료 | 회차, 본문, 출처 링크, 공식·host 구분 |

| 생성 작업 | 재시도·실행 상태, 오래된 결과 덮어쓰기 방지 식별자 |
| 지표 스냅샷 | 시작 시 참석자와 기록 보유 상태, 분자·분모 |

모든 요청·AI 입력 선택에서 공간과 멤버십을 서버에서 검사한다. 화면에서 숨기는 것만으로 비공개를 처리하지 않는다. 수기 저장·책 변경·취소 후 오래된 생성 결과가 반영되지 않도록 한다.

## 15. 출시 확인 기준 — P0

- 공간 간 조회·수정·AI 자료 혼합이 차단된다.
- 비공개 원문은 작성자 외에 노출되지 않으며 개인 경험이 발제문에 그대로 인용되지 않는다.
- 문구·생각 중 하나만 있어도 저장, 둘 다 비어 있으면 저장 불가.
- 기록 유무와 참석 상태가 준비 현황·AI 입력에 각각 정확히 적용된다.
- 마감 자동 생성, 당일 host 재생성, 최초 실패 복구가 구분된다.
- 실패해도 기존 발제문이 보존되고, 수기 저장·취소·책 변경 후 오래된 AI 결과가 덮어쓰지 않는다.
- 시작 스냅샷은 후속 변경으로 달라지지 않는다.
- 링크 재발급 시 기존 링크와 세션은 사용할 수 없고 기록은 유지된다.
- 종료 전후 기록 삭제 제한과 탈퇴 예외가 적용된다.

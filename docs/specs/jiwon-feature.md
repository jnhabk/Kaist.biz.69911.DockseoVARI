- 작성: 김지원
- 날짜: 2026-10-27 (2026-10-28 수정: P0를 2일 1인 프로토타입 범위로 축소)
- 출처: `docs/whytree/jiwon.md`의 `AI 발제 질문 [씨앗]`, 그릴링 세션(Q1~Q22)
- 상태: 개인 설계안. 담당자 등 팀이 정할 부분은 팀 회의에서 확정

## 한 문장 정의

이번 회차 모임장이 멤버들의 밑줄 기록(필요하면 직접 고른 참고자료까지)을 바탕으로, 근거가 붙은 발제 질문 초안을 만들고 다듬어 공개하는 도구.

## 대상과 문제가 드러나는 순간

- **대상:** 이번 회차 모임장. 모임장은 고정된 한 명이 아니라 그 달의 책을 고른 사람이다. 누구나 회차(책 + 모임 날짜)를 만들 수 있고, 만든 사람이 그 회차 모임장이 된다.
- **순간:** 모임 3~4일 전, 모임장이 발제 질문을 준비해야 하는데 멤버들이 어떤 문장에 밑줄을 그었는지, 어디서 생각이 갈렸는지 모르는 때.

## WhyTree에서 이 기능이 맡는 노드

`docs/whytree/jiwon.md` 기준.

- **실선 (주된 why):** 발제 준비 부담 줄이기 → 독서를 지속하는 재미 → 좋은 취미 갖기
- **점선 (부가적인 why):** 해야 할 이야기는 다 하고 오기 → 풍부한 감상 → 좋은 취미 갖기

## 사용자 흐름

전체 설계 기준. P0 프로토타입에서는 1~2단계 대신 샘플 기록 파일을 읽고, 모임장 화면 하나만 본다(아래 "HW6 프로토타입 범위" 참고).

1. 모임장이 회차(책 + 모임 날짜)를 만든다. 만든 사람이 그 회차 모임장이 된다. `P1`
2. 멤버들이 그 회차의 책에 밑줄 문장과 짧은 생각을 남긴다. (입력은 "밑줄 문장 공유" 기능의 범위. 시범 초기에는 구글폼으로 받은 기록을 넣어 시험할 수 있다. P0 프로토타입에서는 샘플 기록 파일을 읽는다. `P0`)
3. (선택) 모임장이 참고자료 칸에 리뷰 영상 메모, 책 소개, 직접 떠올린 주제 등을 텍스트로 붙여 넣는다. `P1`
4. 모임장이 "발제 질문 만들기" 버튼을 누른다. `P0` 버튼이 회차 모임장에게만 보이게 하는 것은 `P1`.
   - 기록을 남긴 멤버가 2명 미만이거나 밑줄이 5개 미만이면 생성되지 않고 최소 기준 메시지(아래 "세부 결정" 참고)가 나온다. `P0`
   - 이때 멤버에게 보낼 기록 요청 문구를 복사할 수 있다. `P1`
5. 질문이 나온다. `P0` 이 결과를 모임장만 볼 수 있는 초안으로 두는 것은 `P1`.
   - 멤버 기록 질문 3~4개. 질문마다 근거 밑줄 1~2개를 인용하고, 작성자 이름 대신 "멤버 3명이 밑줄" 같은 숫자를 보여준다. `P0`
   - 질문 유형을 섞는다. 공감 지점(여러 명이 같은 문장에 밑줄), 의견이 갈린 지점(같은 장면을 다르게 읽음), 숨은 지점(한 명만 주목). `P1`
   - "기록 밖 질문" 최대 1~2개. 참고자료에는 있지만 기록에는 없는 주제로 만들고, 표시를 따로 붙이고, 근거로 참고자료의 해당 문단을 보여준다. 이 질문까지 합치면 전체는 5개 안팎이 된다. `P1`
6. 모임장이 질문을 수정하거나 지우거나 다시 생성한다. `P1`
7. 모임장이 "공개"를 누르면 멤버에게 질문이 보인다. 공개 전에는 모임장만 볼 수 있다. `P1`
8. (P2) 모임장이 다른 멤버에게 모임장 역할을 넘긴다. 시범 기간에는 DB에서 직접 바꾼다.

- **위치:** `prototypes/jiwon/`
- **만드는 사람과 기간:** 김지원 1인, 2일
- **보는 사람:** 모임장 화면 하나만 본다. 멤버 화면은 없다.

**있는 것**

- `prototypes/jiwon/`의 샘플 멤버 기록 파일(JSON 또는 CSV) 읽기
- "발제 질문 만들기" 버튼
- 최소 기준(기록한 멤버 2명, 밑줄 5개) 확인과 메시지 하나
- Claude Haiku 5.5로 멤버 기록 질문 3~4개 생성
- 질문마다 근거 밑줄 1~2개 인용과 "멤버 n명이 밑줄" 숫자 표시 (이름 없음)
- 임시 라벨 검증: 없는 라벨을 근거로 든 질문은 버림, 인용문은 원본 파일에서 가져옴
- API 실패 또는 남은 질문 0개 → "지금 만들 수 없어요" + "다시 시도"

- 자동 재생성과 "질문이 적게 나왔어요" 표시

- 질문 유형 섞기
- 기록 요청 문구
- 모임장 참고자료 칸과 "기록 밖 질문"
- 밑줄 입력 화면

## 세부 결정

| 항목 | 결정 |
|-|-|
| 재료 | ① 멤버의 밑줄 문장과 짧은 생각 ② 서지 정보(제목, 저자, 출판사 책 소개 — 맥락용) ③ 모임장 참고자료(선택). 외부 리뷰 자동 수집과 LLM 사전 지식(줄거리 등)은 쓰지 않는다. |
| 입력 | 이 기능은 "회차의 책에 연결된 밑줄 문장 + 짧은 생각(선택)"이라는 데이터 형태만 약속받는다. P0 프로토타입에서는 이 형태를 `prototypes/jiwon/`의 샘플 파일로 대신한다. |
| 생성 | 모임장이 버튼을 눌러 생성한다. 다시 만들 수 있다. 참고자료만으로는 생성되지 않는다. |
| 최소 기준 메시지 | 메시지는 하나다. "기록이 더 필요해요. 멤버 n명, 밑줄 m개가 더 있어야 질문을 만들 수 있어요." n = 기록을 남긴 멤버가 2명이 되려면 더 필요한 멤버 수, m = 밑줄이 5개가 되려면 더 필요한 밑줄 수. 이미 채운 쪽은 문구에서 뺀다(예: "기록이 더 필요해요. 밑줄 2개가 더 있어야 질문을 만들 수 있어요."). |
| 익명 | 발제 질문 화면에서는 모임장을 포함해 누구에게도 밑줄 작성자를 보여주지 않는다. 인용은 책 문장(밑줄)만 하고, 멤버의 생각은 질문을 만드는 데에만 쓰고 원문을 보여주지 않는다. AI에게도 사용자 ID나 이름을 보내지 않는다. |
| 할루시네이션 방지 | 생성할 때마다 밑줄과 참고자료 문단에 임시 라벨(`#1`, `#2`…)을 붙여 AI에게 보낸다. 라벨은 사용자 ID가 아니라 한 번의 생성에서만 쓰는 번호다. AI는 근거로 라벨만 고른다. 화면의 인용문은 코드가 원본(P0: 샘플 파일, P1 이후: DB)에서 원래 문장을 가져와 보여준다. 존재하지 않는 라벨을 근거로 든 질문은 버린다. |
| 성공 기준 | 실제 모임에서 AI 질문 중 그대로 또는 고쳐서 쓴 질문 수(목표: 5개 중 3개 이상). 모임장에게 준비 시간이 예전보다 어땠는지 한 문항으로 묻는다. |

## AI 모델과 실패 시 동작

- **모델:** Claude Haiku 5.5 (`claude-haiku-5-5`). AI가 하는 일은 라벨을 고르고 짧은 질문을 쓰는 것이라 작은 모델로 충분하고, 무료 한도 소진 위험(PREMORTEM 11번)을 피한다.
- **API 키:** 서버 쪽 `.env`에만 두고, 웹 페이지(브라우저로 보내는 코드)에는 절대 넣지 않는다. `.env`는 `.gitignore`에 넣는다.
- **실패 시 동작:**
  1. **API 오류, 시간 초과, 한도 초과:** "지금 만들 수 없어요" 안내와 "다시 시도" 버튼을 보여준다. `P0` P0에서는 같은 화면의 직전 결과를 지우지 않는다. 저장된 초안을 지우지 않는 것은 `P1`.
  2. **검증 후 남은 질문이 적을 때** (없는 라벨이나 형식 오류로 버려진 경우):
     - P0: 남은 질문이 1개 이상이면 그대로 보여준다. 0개면 1번과 같은 화면을 보여준다.
     - P1: 남은 질문이 3개 미만이면 자동으로 한 번 더 생성한다. 그래도 부족하면 남은 질문만 보여주고 "질문이 적게 나왔어요"라고 표시한다.
  3. **데모 당일:** 미리 생성해 둔 결과 화면이나 녹화본을 준비한다(PREMORTEM 11번 대응).
- 어떤 경우에도 근거를 확인하지 못한 질문은 화면에 나오지 않는다.

- 담당자는 팀이 정한다. 김지원의 10월 일정 제약(PREMORTEM 7번)을 미리 공유한다.

## 열린 문제

- **밑줄 공유 피드의 작성자 표시:** 피드에 이름이 보이면 같은 문장을 찾아 작성자를 알 수 있어, 이 기능의 익명이 무력해진다. 밑줄 공유 기능을 설계할 때 정한다.
- **멤버가 2명뿐일 때의 익명:** 최소 기준은 기록한 멤버 2명이다. 이때 한 멤버는 자기 것이 아닌 밑줄을 보고 나머지 한 명이 누구인지 알 수 있다. "멤버 1명이 밑줄"이라는 숫자 표시도 같은 단서가 된다.
